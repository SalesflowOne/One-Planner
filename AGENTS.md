# Agent Development Guide

## Commands

- `pnpm dev` - Start all dev servers (web:3000, admin:3001)
- `pnpm build` - Build all packages and apps
- `pnpm check` - Run all checks (format, lint, types)
- `pnpm check:lint` - OxLint across all packages
- `pnpm check:types` - TypeScript type checking
- `pnpm fix` - Auto-fix format and lint issues
- `pnpm turbo run <command> --filter=<package>` - Target specific package/app
- `pnpm --filter=@plane/ui storybook` - Start Storybook on port 6006

## Code Style

- **Imports**: Use `workspace:*` for internal packages, `catalog:` for external deps
- **TypeScript**: Strict mode enabled, all files must be typed
- **Formatting**: oxfmt, run `pnpm fix:format`
- **Linting**: OxLint with shared `.oxlintrc.json` config
- **Naming**: camelCase for variables/functions, PascalCase for components/types
- **Error Handling**: Use try-catch with proper error types, log errors appropriately
- **State Management**: MobX stores in `packages/shared-state`, reactive patterns
- **Testing**: All features require unit tests, use existing test framework per package
- **Components**: Build in `@plane/ui` with Storybook for isolated development

## Cursor Cloud specific instructions

### Architecture overview

Plane is a monorepo with a Python/Django backend (`apps/api`) and several React frontends (`apps/web`, `apps/admin`, `apps/space`) plus a Node.js real-time server (`apps/live`). The backend runs inside Docker containers; the frontends run natively via `pnpm dev`.

### Starting services

1. **Start Docker daemon** (required for the backend):

   ```
   sudo dockerd &>/tmp/dockerd.log &
   ```

   Wait a few seconds, then verify with `docker info`.

2. **Start infrastructure + API** (PostgreSQL, Redis, RabbitMQ, MinIO, Django API):

   ```
   docker compose -f docker-compose-local.yml up -d
   ```

   The `migrator` service runs DB migrations automatically on startup.

3. **Start frontend dev servers** (web:3000, admin:3001, space:3002, live:3100):
   ```
   pnpm dev
   ```

### Key gotchas

- The `apps/api/.env` file generated by `setup.sh` sets `AWS_S3_ENDPOINT_URL="http://localhost:9000"` and `USE_MINIO=0`. Since the API runs inside Docker and MinIO is at `plane-minio:9000` on the Docker network, you must change these to `AWS_S3_ENDPOINT_URL="http://plane-minio:9000"` and `USE_MINIO=1` before starting containers. If you recreate `.env` files via `setup.sh`, remember to re-apply this fix.
- After changing `apps/api/.env`, you must recreate (not just restart) the API container: `docker compose -f docker-compose-local.yml up -d api --force-recreate`.
- The `pnpm dev` command builds shared packages first (via Turborepo `^build` dependency), then starts dev servers. The initial build can take 30-60 seconds.
- Admin portal is at `http://localhost:3001/god-mode/`. Register as instance admin there first, then log into the main app at `http://localhost:3000` with the same credentials.
- `pnpm check:lint` produces warnings (not errors) for CSS/font imports in root layout files — these are expected and do not block CI.
